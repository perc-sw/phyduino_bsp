Phyduino Board Support - Architecture

Read this first when coming back to the project.

The one rule

platform/ is exactly what users get. The release zip is platform/ and nothing else. Everything outside it is tooling, docs or tests.

How a sketch is built

 Arduino IDE / arduino-cli
   │  reads platform/boards.txt   (which board: mcu, variant, USB ids, upload)
   │  reads platform/platform.txt (how to compile/link: the recipes)
   ▼
 compile ──► sketch .ino/.cpp
         ──► platform/cores/phyduino/**          → core.a
         ──► platform/variants/<board>/*.cpp     → core.a
         ──► platform/libraries/<used libs>/src  → objects
   every compile gets:
     @system/<board>/compile_flags.txt   (SDK -D defines)
     -isystem system/<board>/include     (all SDK + TinyUSB headers)
   ▼
 link ──► objects + core.a
       + system/<board>/lib/boot2.o
       + system/<board>/lib/libpico.a   (--whole-archive)
       @system/<board>/link_flags.txt   (--wrap list, specs, gc-sections)
       -T system/<board>/memmap.ld
   ▼
 <sketch>.elf ──► picotool uf2 convert ──► <sketch>.uf2
   ▼
 upload: 1200-baud touch → board reboots to BOOTSEL → tools/uf2_upload copies the
         .uf2 to the RPI-RP2 drive (or picotool load -x as fallback; ADR 007)

The SDK bundle (platform/system/<board>/)

Generated by sdk-builder/, committed to git (ADR 002), never edited by hand. It contains the pico-sdk compiled for one board, so the Arduino build needs only the ARM compiler and is fast. Sketches can use any SDK API that is in the bundle (#include "hardware/pwm.h"). The list of SDK components is SDK_COMPONENTS in sdk-builder/CMakeLists.txt.

Why --whole-archive: the SDK registers start-up code (clock init, runtime init) in linker sections that nothing references by name. A normal archive search would silently drop it. --gc-sections still removes unused code.

Start-up order

cores/phyduino/main.cpp:

  1. 1

    pico-sdk runtime (crt0, clocks, runtime_init)

  2. 2

    init(): ADC, TinyUSB + its 1 ms background task

  3. 3

    initVariant(): board chips (Phyduino Pico: MAX11635 ADC, STUSB4500 power profiles)

  4. 4

    setup(), then loop() forever

Conventions

  • Hooks a variant must provide (initVariant and the variantAnalog* functions in Arduino.h) have no weak default in the core. The core is linked from an archive, where a weak default could silently win; a missing hook is a link error instead.
  • Upstream code is untouched: extern/ (submodules) and platform/cores/phyduino/api/ (vendored ArduinoCore-API, see UPSTREAM.md).
  • Design decisions and their reasons: docs/decisions/.
  • Step-by-step recipes for recurring jobs: docs/maintenance/.
  • Two ways to build the same code: arduino-cli (tests/compile_all.py) and CMake (cmake --workflow --preset phyduino_pico, strict warnings), plus PC-side unit tests (cmake --workflow --preset host-tests). All three run in CI. If recipe.c.combine.pattern changes, update the link step in cmake/phyduino.cmake too.

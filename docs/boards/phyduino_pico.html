USB Power Delivery

VBUS feeds the on-board regulator and the VIN pin, so VIN carries whatever voltage the USB-PD charger supplies. Tools > USB-PD Power (VIN) sets the highest voltage the board asks for; at start-up initVariant() loads the matching sink profiles into the STUSB4500 (variant.cpp). The 10 W limit (schematic) sets the current of the top profile:

Use chip's stored settings (NVM)left as loaded at power-up5 V on a Phyduino board

An ordinary USB port always gives 5 V. A charger supplies the highest profile it can. The menu writes the chip's working registers only, never its NVM, and the board renegotiates only if they differ from what the chip already holds. A sketch can change them with stusb4500::setProfiles() and read the contract and measured VBUS (see stusb4500.h and tests/sketches/usbpd_status).

At plug-in, before any sketch runs (and during uploads), the chip negotiates from its NVM. ST's factory NVM asks for up to 20 V at 1 A, so Phyduino boards have their NVM set to 5 V only, once per board, with tests/sketches/usbpd_nvm (hardware checklist item 19). The NVM is good for about 1000 writes, which is why only that tool writes it.

The register addresses come from ST's register map, not the datasheet; tests/hardware-checklist.md item 14 checks them.

Things to know

  • Analog full scale differs: A0–A2 = 3.3 V, A3–A5 = 2.048 V. With the default 10-bit analogRead(), volts = reading * 3.3 / 1023 on A0–A2 but reading * 2.048 / 1023 on A3–A5. analogReference() does nothing.
  • No I2C pull-ups on the board. Wire enables the RP2040's weak internal pull-ups; use 4.7 kΩ to 3.3 V for longer wires or 400 kHz.
  • GPIO25 (SCL) needs 12 mA drive (schematic note); Wire sets it.
  • PWM slices: pins on the same PWM slice share a frequency: D0/D1/D8/D9, D2/D3, D4/D5/SDA/SCL, D6/D11/A0/A1, D10/D12/A2, D7/D13. tone() on one changes the others' frequency. D1/D8, D0/D9, D6/A0, D11/A1 and D12/A2 are also the same channel, so they share the duty cycle too (table under analogWrite() in the API reference).
  • USB-PD bus: the STUSB4500 is on I2C1 (GPIO2/3). phyduino_pico_bios sets it to i2c0 by mistake; this core uses I2C1. Wire (I2C0) is separate.
  • CPU speed: Tools > CPU Speed, 50–200 MHz, default 133 MHz. Above 133 MHz the core voltage is raised to 1.15 V (the RP2040's rating for 200 MHz). 175 MHz cannot be made from the 12 MHz crystal, so 176 MHz is offered. millis(), delay(), USB, the ADCs and UART/SPI/I2C/PWM rates are unaffected. The fastest SPI clock is half the peripheral clock: CPU speed / 2 up to 133 MHz (66.5 MHz at the default), but 24 MHz above 133 MHz, where the peripherals run from the 48 MHz USB clock. The lowest tone()/PWM frequency scales with the clock: about 3 Hz at 50 MHz, 8 Hz at 133 MHz, 12 Hz at 200 MHz.
  • Optimise: Tools > Optimize picks -Os (default, smallest), -O2, -O3 (fastest) or -Og (for debugging) for the sketch, core and libraries.
  • C++ standard: Tools > C++ Standard picks C++14, 17 (default), 20 or 23 (GNU dialects) for the sketch, core and libraries. C++20 and later warn on ++/-- of a volatile variable (common in interrupt sketches); the code still works.

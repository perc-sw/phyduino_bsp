Phyduino Board Support - Maintenance - Dev setup: use this checkout in the Arduino IDE

The SDK bundle is committed, so no build step is needed to use the core. Only sdk-builder/ needs the submodules.

Once per machine

  1. 1

    Install the Arm GNU toolchain (arm-none-eabi), picotool, Arduino IDE 2.x and/or arduino-cli. For sdk-builder/ also: CMake ≥ 3.20, Ninja, Python 3.

  2. 2

    Clone with submodules:

    git clone --recurse-submodules <repo-url>

    (Already cloned? git submodule update --init --recursive.)

    Turn on the repo's git hooks (after each commit they remind you when 10 or more CHANGELOG entries have built up since the last tag; package/prerelease_reminder.py):

    git config core.hooksPath .githooks
  3. 3

    Link platform/ into your sketchbook as hardware/phyduino/rp2 (Windows, in cmd):

    mklink /J "%USERPROFILE%\Documents\Arduino\hardware\phyduino\rp2" "C:\repos\student_workshop\phyduino_bsp\platform"

    Linux/macOS: ln -s "$PWD/platform" ~/Arduino/hardware/phyduino/rp2

  4. 4

    Create platform/platform.local.txt (git-ignored) with your tool paths:

    compiler.path=C:/Program Files (x86)/Arm/GNU Toolchain mingw-w64-i686-arm-none-eabi/bin/
tools.picotool.path=C:/Program Files (x86)/picotool

    compiler.path must end with /.

  5. 5

    Restart the IDE. Tools → Board → Phyduino Boards (in sketchbook) → Phyduino Pico. If the Board Manager version is also installed, the IDE lists both; pick the "(in sketchbook)" one. While this link is in the sketchbook, Boards Manager hides the published Phyduino package, so switch to a sketchbook without it before testing a Board Manager install. The other way round, arduino-cli can build with the installed Board Manager copy instead of this link when the versions differ, so remove the installed copy (Boards Manager → Remove) when you go back to development.

Every change

python tests/compile_all.py

compiles every test sketch and library example through arduino-cli, and

cmake --workflow --preset phyduino_pico

builds the same code through CMake with -Werror (cmake-verify.html), and

cmake --workflow --preset host-tests

runs the PC-side unit tests (host-tests.html). Then upload the affected sketches to a board and run the relevant items in tests/hardware-checklist.md.

First upload to a new board

A board that has never run this core does not answer the 1200-baud touch: slide SW1 to GND (BOOTSEL), press reset, upload, slide SW1 back to 3.3 V. After that, uploads work from the IDE with no buttons.

Uploads need no USB driver: the upload script copies the sketch to the RPI-RP2 drive (ADR 007). On Windows, picotool's own upload path additionally needs a WinUSB driver (Zadig); it is only a fallback and is not required.
